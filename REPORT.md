## 4. Транзитивные зависимости

Транзитивные зависимости — это пакеты, которые проект не импортирует напрямую, но которые требуются одной из прямых зависимостей.

| Прямая зависимость | Пример транзитивной зависимости | Почему нужна |
|---|---|---|
| `requests` | `urllib3==2.8.0` | низкоуровневый HTTP-клиент, поверх которого построен `requests` |
| `pandas` | `python-dateutil==2.9.0.post0` | разбор дат и временны́х строк |
| `matplotlib` | `contourpy==1.4.0` | вычисление контуров для отдельных типов графиков |

Именно поэтому `numpy` не нужно добавлять как прямую зависимость: скрипт `plt_temp.py` не вызывает `import numpy` явно. `numpy` устанавливается автоматически как транзитивная зависимость `pandas` и `matplotlib`.

## 6. Проверка групп Poetry

### Вариант 1: только основная группа (без `test` и `dev`)

```bash
poetry install --only main
```

| Инструмент | Доступен? |
|---|---|
| `pytest` | ❌ не установлен |
| `ruff` | ❌ не установлен |
| Основной скрипт | ✅ запускается |

**Почему:** `pytest` входит в группу `test`, `ruff` — в группу `dev`. При `--only main` Poetry устанавливает исключительно пакеты из основных зависимостей.

---

### Вариант 2: только группа `test`

```bash
poetry install --only test
```

| Инструмент | Доступен? |
|---|---|
| `pytest` | ✅ установлен |
| `ruff` | ❌ не установлен |
| Основной скрипт | ❌ не запускается (`requests`, `pandas`, `matplotlib` отсутствуют) |

**Почему:** при `--only test` основная группа не устанавливается. `pytest` есть, но скрипт упадёт с `ModuleNotFoundError`.

## 7. Обновление зависимости (задание 9)

Исходное ограничение в `pyproject.toml` для `requests`:

```toml
"requests (>=2.30,<3.0.0)"
```

Команда обновления только одной зависимости:

```bash
poetry update requests
```

Результат `poetry show --outdated` перед обновлением — вывод пуст: актуально установленная версия `requests==2.34.2` уже является самой свежей в допустимом диапазоне `>=2.30,<3.0.0`.

**Что изменилось:**

| Параметр | До | После |
|---|---|---|
| Ограничение в `pyproject.toml` | `>=2.30,<3.0.0` | без изменений |
| Установленная версия (`poetry.lock`) | `2.34.2` | `2.34.2` (без изменений) |
| Транзитивные зависимости | без изменений | без изменений |

**Вывод:** более новой совместимой версии `requests` в диапазоне `<3.0.0` не существует — `2.34.2` и есть последний выпуск ветки 2.x. Это не ошибка: `poetry.lock` корректно зафиксировал максимально актуальную версию. Обновление не вышло за заданный диапазон, потому что следующая мажорная версия (`3.x`) явно запрещена ограничением `<3.0.0`.

## 9. Сравнение подходов: `venv + pip` и Poetry

| Критерий | `venv + pip + requirements.txt` | Poetry (`pyproject.toml` + `poetry.lock`) |
|---|---|---|
| **Воспроизводимость** | `requirements.txt` с точными версиями (`==`) гарантирует идентичный набор пакетов при `pip install -r requirements.txt` | `poetry.lock` фиксирует точные версии всех прямых и транзитивных зависимостей с хэшами; `poetry install` детерминирован по определению |
| **Разделение зависимостей** | Нет встроенного механизма; обычно ведут отдельные файлы (`requirements-dev.txt`) | Группы `[dependency-groups]` (`test`, `dev`) прямо в `pyproject.toml` |
| **Добавление пакетов** | `pip install` → ручное обновление `requirements.txt` | `poetry add` обновляет `pyproject.toml` и `poetry.lock` атомарно |
| **Обновление** | Нет встроенного контроля диапазонов; нужно вручную редактировать файл | `poetry update <pkg>` обновляет в рамках заданного диапазона, не трогая остальные пакеты |
| **Проверка целостности** | Нет (если не использовать `--require-hashes`) | Хэши всех пакетов хранятся в `poetry.lock` и проверяются при установке |
| **Что обеспечивает воспроизводимость** | Точные версии (`==`) в `requirements.txt` | Единый lock-файл с хэшами + диапазоны в `pyproject.toml` как «контракт совместимости» |
